版本 1.0 / 2026-09-15。面向接手开发的 AI 和开发者。

## 2. 信息架构与路由

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/` | 首页 | 个人定位、精选笔记、项目实践、关于 |
| `/notes/` | 工程笔记 | 全部已发布文章、主题筛选、搜索入口 |
| `/notes/<slug>/` | 文章详情 | 静态生成，每篇唯一永久链接 |
| `/search/` | 搜索 | 搜索已发布文章的标题和正文 |
| `/404.html` | 未找到 | 返回首页、工程笔记的有效入口 |
| `/rss.xml` | RSS | 仅已发布文章 |
| `/sitemap-index.xml` 或 `/sitemap.xml` | 站点地图 | 由集成实际产物决定，robots 引用真实路径 |

导航保持四项：**首页 / 工程笔记 / 项目实践 / 关于**。工程笔记进入 `/notes/`；项目实践和关于分别进入首页的 `#project`、`#about`。文章页也使用这些地址。搜索使用独立的文字或图标入口，主题按钮放在右端。

当前导航高亮规则：列表和文章详情高亮工程笔记；首页滚动到项目或关于时高亮对应项；回到首页顶部或首页精选笔记时高亮首页。搜索页不错误高亮首页。每次最多一个 `aria-current`，使用真实链接，不用 `href="#"` 代替未完成功能。

不要把技术领域与文章类型混成两套并列导航。可筛选领域固定为：全部笔记、系统建模、复杂前端、平台架构、工程管理。架构设计、技术决策、团队与交付可以作为文章类型元信息，不再增加第二排筛选。

## 3. 页面规格

### 3.1 首页

顺序：导航 → 个人介绍与工作方法图 → 工程笔记（含分类）→ 项目实践 → 关于 → 页脚。

#### 个人介绍

- 沿用原型的左右双栏：左侧定位、简介、行动入口；右侧工作方法结构图。
- 标题保持两行的自然节奏，允许响应式换行，不用不可换行空格或固定高度卡死。
- 主按钮「阅读工程笔记」进入 `/notes/`；次入口「了解我的工作」滚动至关于区域。
- 控制首屏高度。1440×900、100% 缩放时，工程笔记标题应进入首屏，最好可见首张卡片上缘。建议 hero 上下留白 56～64px、图示高度 340～400px，总高度约 500～540px。最终以真实中文内容调整。
- 手机端标题与主按钮优先；工作方法图改为紧凑布局，仍保留中文节点，减少辅助英文和空白。禁止为了缩图而把中文缩至小字号。
- 图示保持概念性，不虚构为 SE-MBSE 的完整生产架构。无交互的图形节点不使用手型鼠标或按钮语义。

#### 工程笔记

- 把原型中独立的 FOCUS AREAS 分类栏移到「工程笔记」标题下方、内容列表上方。标题、筛选、结果成为一个连续区域。
- 保留蓝色选中态和明确边框，中文辅助标题用「按主题浏览」，英文可作次要装饰。
- 首页展示筛选结果的前 3 篇。仅第一篇采用原型的横向精选卡，其余采用紧凑文章行；没有结果时展示空状态。
- 排序：编辑精选顺序优先，其余按发布日期倒序。显示「共 N 篇，当前展示 M 篇」；所有计数来自同一份已发布集合。
- 「查看全部笔记」进入 `/notes/?topic=<当前领域>`；全部领域省略 topic 参数。
- 当前原型的准备中选题，正式站首页不展示；留在本地写作计划中。未发表草稿不计入文章数。
- 如果尚无正式文章，诚实展示「第一篇工程笔记正在整理中」，隐藏精选卡。可以继续完成网站功能，但不能凭空生成成果填充。

#### 项目实践

- 保留深蓝背景、左侧说明与右侧 SE-MBSE 卡片，形成明确的视觉区隔。
- 卡片信息：项目名称、用途、个人角色、主要职责；后续才加入有依据的挑战与成果。
- 当前没有独立案例正文时，不显示「查看完整案例」假入口。有关联已发布文章时可展示最多 3 个文章链接。
- 正文和角色说明使用至少 14～16px 的可读字号；手机端单列。

#### 关于与页脚

- 保留姓名字标，正文陈述已确认身份与写作方向。不要重复整段首页宣传文案。
- GitHub/邮箱配置存在时显示；没有时不生成空链接或编造地址。
- 页脚包含署名、RSS、回到顶部。版权年份按构建年份生成。网站代码与文章许可分别配置，不擅自宣称所有材料采用某种开源许可。

### 3.2 工程笔记列表 `/notes/`

- 单一页面 H1「工程笔记」，一句简洁说明，分类筛选，搜索入口，结果数量，文章列表。
- 默认全部文章；V1 面向不超过 50 篇的个人博客，直接静态输出全集，浏览器进行领域筛选。超过这一规模再设计分页，避免交付半套分页。
- 每项提供标题、1～2 行摘要、发布日期、领域/文章类型。整项只有一个主链接，避免嵌套链接。长标题可换行，不强制单行截断。
- `?topic=modeling|frontend|architecture|management` 表达筛选状态。选择领域更新 URL；刷新和浏览器前进/后退恢复状态；无效参数按全部处理。
- 单选分类使用原生按钮加 `aria-pressed`，放入有中文名称的 group。它是筛选器，不强行使用不完整的 tab/tabpanel 语义。
- 点击后保持控件在视口中的位置，不把用户突然送回页首；结果用温和的 `aria-live` 提示。
- 空分类可保留但明确显示 0，不显示为失效控件；提供恢复全部按钮。不要让所有分类都显示同一张卡假装筛选。
- JavaScript 禁用时仍能读到静态文章列表并打开文章；隐藏无法运行的筛选控件或提供说明。

### 3.3 文章详情

顺序：返回笔记 → 分类 → 标题 → 摘要 → 作者和日期 → 手机折叠目录 → 正文 → 相关文章/返回列表。

- 桌面正文宽度 720～760px；目录宽 200～220px；栏间距 40～64px。
- 手机目录放在标题和摘要之后、正文之前，使用 `<details><summary>本篇目录</summary>` 默认收起。必须调整真实 DOM 顺序，不能只使用 CSS order 造成视觉与朗读顺序不一致。
- H2/H3 自动生成稳定且去重的锚点与目录；目录文本跟正文一致。当前章节高亮，点击目录后标题不被固定导航遮挡。
- 正文支持段落、列表、引用、图片及说明、表格、代码。大表格和代码在自身容器横向滚动，不让整页横向滚动。
- 代码块显示语言、可选文件名、复制按钮；复制是纯文本，保留换行，不带 HTML 标签和行号。权限拒绝时提示可选中复制；成功状态通过 live region 提示。
- 代码高亮适配深浅色；普通代码字号至少 14px，横向溢出时滚动。
- 技术图优先 SVG 或清晰图片，提供 alt 和说明；复杂图片可打开原图。无必要不引入整套图表运行时。
- 已发布文章显示实际发布日期；更新日仅在确有内容更新且晚于发布日期时显示。阅读时长可选，若展示则由内容计算并注明「约」。
- 有相关文章才展示相关文章区域；没有系列信息则不出现失效的上一篇/下一篇。
- 草稿只在本地开发预览，明显显示草稿提示；生产构建完全不产生草稿页面。`noindex` 不能替代排除产物。

### 3.4 搜索

- 使用 Pagefind 构建静态全文索引，无需自建搜索服务。[Pagefind 文档](https://pagefind.app/docs/)
- `/search/` 有明确标签的输入框；支持 `?q=` 初始化，输入更新采用 replaceState，避免每个字符占一个历史记录。
- 状态至少覆盖：未输入、索引加载中、匹配结果、无结果、索引加载失败。错误状态提供重试和笔记列表入口，不是无限转圈。
- 搜索范围限定正式文章标题和正文，排除导航、页脚、作者介绍、草稿和原型。
- 结果显示标题、摘要片段与链接。测试中文词组、英文技术词、空格及符号，不假定中文效果已验证。
- 搜索脚本按需加载；即使搜索暂时失败，文章阅读不受影响。

## 4. 视觉与排版规格

### 4.1 保留的设计语言

保留「清晰的技术出版物」气质：白底、石墨色正文、工程蓝强调、细分隔线、低强度阴影和有限圆角。保留 HF 字标、姓名字标、工作方法图及深蓝项目区。不更换为大渐变、大面积发光、粒子背景或堆叠仪表盘卡片。

原型图示的轻微倾斜可保留在桌面装饰图中，手机取消。正文、代码和可操作控件不能倾斜。

### 4.2 颜色基线

| Token | 浅色 | 深色 |
| --- | --- | --- |
| 页面背景 | `#FFFFFF` | `#101722` |
| 次级背景 | `#F5F7FA` | `#161F2D` |
| 正文 | `#172234` | `#E6EDF7` |
| 次级文字 | `#616E7E` | `#A1AFC2` |
| 强调/链接 | `#2458D5` | `#8AAFFF` |
| 边线 | `#E0E6EC` | `#303E51` |
| 浅强调背景 | `#EDF3FF` | `#202F47` |

这些是原型色值，不代表所有组合均已通过对比度检查。普通文字目标至少 4.5:1；大字按适用条件至少 3:1。悬停、选中、禁用、代码主题和深蓝区域分别验证。[W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

### 4.3 尺寸与文字

统一使用 rem；下列 px 是默认根字号 16px 时的参考值，不锁死浏览器字体设置。

| 项目 | 桌面 | 手机 |
| --- | --- | --- |
| 页面最大内容宽度 | 1152px | 容器自适应 |
| 左右安全边距 | 最少 32～40px | 20px；320px 宽时可 16px |
| 导航 | 14～16px | 14px，允许两行布局 |
| 首页大标题 | 40～44px | 30～34px |
| 页面/文章 H1 | 36～40px | 28～32px |
| 区块 H2 | 28～32px | 24～28px |
| 文章卡标题 | 22～26px | 20～24px |
| 正文/文章摘要 | 16～18px | 16～17px |
| 日期、说明、按钮 | 14px | 14px |
| 非关键装饰英文 | 最低 12px | 可隐藏非必要装饰 |

中文正文行高 1.8～1.95，标题行高 1.35～1.5。长段落拆分；默认左对齐，不强制两端对齐。字号先保证阅读，再调整容器高度，不能靠缩字解决排版。

间距尺度采用 4/8/12/16/24/32/48/64px。卡片 padding 桌面 28～32px、手机 20～24px；区块留白桌面 56～64px、手机 36～44px。圆角 4～8px，按钮 44px 最小目标高度为本项目触控设计要求。

### 4.4 响应式与无障碍

- 建议断点：760px 以下单栏，760～1024px 紧凑双栏，1024px 以上完整桌面布局。实际以内容宽度调整。
- 顶栏可保留原型的手机双行样式，避免引入没有必要的复杂菜单。
- 固定导航高度会随设备及字号变化；用 ResizeObserver 更新 CSS 变量，或等效可靠方案，让锚点偏移始终为导航实测高度 + 16px。
- Tab 顺序遵循 DOM；每个操作可用键盘完成；焦点轮廓清晰；有跳至正文入口。
- 主题偏好本地保存；读取受限不报错；首次默认系统偏好。尽量在首屏绘制前设置主题，减少白屏闪烁。
- 尊重 `prefers-reduced-motion`；交互过渡建议 120～200ms。
- 320 CSS px 下无非必要的整页横向滚动；文字放大至 200% 后仍可读可操作。二维表格等允许在局部容器滚动。[W3C 重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) · [文字缩放](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)

## 5. 技术架构

### 5.1 技术选择

Astro + TypeScript + Markdown/MDX，纯静态输出。pnpm 管理依赖并提交锁文件。仅在交互演示需要时加入 React，不把全部文章页面变成 React 单页应用。

用 Astro Content Collections 管理文章并校验字段；开发时选定稳定版本并确认相应 API，锁定实际依赖和兼容 Node 版本。不复制旧版教程中的 API 拼接使用。[Astro 内容集合文档](https://docs.astro.build/en/guides/content-collections/)

### 5.3 内容模型

```yaml
title: 复杂系统的模块边界，应该从哪里划起？
slug: defining-module-boundaries
description: 从变化原因、规则归属和协作成本出发，思考模块边界。
status: draft
topics: [modeling, architecture]
kind: architecture
featuredOrder: 1
# publishedAt: 正式发表时填写 YYYY-MM-DD
# updatedAt: 有内容更新时填写 YYYY-MM-DD
```

字段规则：title、slug、description、topics、status 必填；topics 为受控枚举；kind 可选，值为 architecture/decision/delivery；featuredOrder 可选正整数；publishedAt 在 published 时必填。封面可选，应附 alt，不强制每篇配装饰图片。

slug 只允许小写英文、数字和连字符，唯一且长期稳定；重复 slug、未知领域、已发布缺日期、无效日期或更新早于发表时构建失败。不得以 Git 提交日期代替用户的发表日期。

全站使用同一函数返回公开内容：status 为 published 且发布日期不晚于构建日期。未来日期仅在下一次合适的构建后上线；V1 不宣称实现自动定时发布。

草稿与未来文章从静态路径、导航列表、相关文章、RSS、sitemap、Pagefind 索引及公开 JSON 中一起排除。生产 dist 内不得残留上一轮产物，构建前清理输出目录。预览草稿只供本地开发，公开 CI 禁止开启预览标记。

### 5.4 URL 与静态托管

通过统一 URL helper 处理 base 路径。不要在组件里散落硬编码 `/styles.css` 或 `/notes/...`。

- 用户站点：仓库 `<username>.github.io`；网站地址 `https://<username>.github.io/`，base `/`。
- 项目站点：如仓库 `hanfei-blog`；网站地址 `https://<username>.github.io/hanfei-blog/`，base `/hanfei-blog/`。
- 文章使用静态目录页输出，直接打开或刷新详情页应返回正常页面；不要依赖 SPA 的 404 回退。
- 资源、RSS、sitemap、canonical、搜索资源与搜索结果链接都必须覆盖根路径和子路径两种情况。
- 未知正式域名时本地可运行；正式构建应拒绝占位域名，不能把 localhost 或示例用户名写入公开 SEO 产物。

### 5.5 SEO 与性能

- 每页唯一 title 和 description；文章页包含 Article 结构化数据，作者、日期与实际内容相符。
- canonical 指向正式无筛选参数页面；领域筛选参数不制造重复索引页。搜索页与 404 使用 noindex；站点地图仅含正式内容页面。
- HTML 正文静态输出；配置 lang=zh-CN；首页作者信息与文章署名一致。
- 使用系统字体优先，避免首屏依赖远程中文字体。图像带尺寸或 aspect-ratio，首屏外图片延迟加载。
- Pagefind 在 Astro 输出后建立索引，再打包完整 dist。普通文章页不预加载搜索运行时。
- 性能目标是待验证的开发预算：生产构建手机 Lighthouse Performance ≥90、Accessibility ≥95。记录设备/模拟条件与实测结果，分数不可代替阅读与键盘检查。

## 6. GitHub Pages 部署

GitHub Pages 托管 HTML/CSS/JS 静态文件；免费账户可用公开仓库，因此网站应与 SE-MBSE 源码保持独立。[GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

Astro 官方支持通过 GitHub Actions 部署到 Pages。接手者按所选版本参考官方流程，确保加入项目自己的校验和 Pagefind 构建步骤。[Astro Pages 部署文档](https://docs.astro.build/en/guides/deploy/github/)

流水线顺序：

1. checkout 网站仓库。
2. 安装锁定 Node、pnpm，按锁文件安装依赖。
3. 校验类型、内容 schema、链接和 URL 配置。
4. 生产构建 Astro，再生成 Pagefind 索引。
5. 检查 dist 无草稿/原型文件，校验根路径或当前 base 的内部链接。
6. 上传 Pages artifact，仅包括 dist。
7. 通过 GitHub Pages 部署，并验证真实公开网址。

按官方部署机制配置最小必要权限（contents 读取、部署所需 pages 写入和 id-token 写入）与 github-pages 环境；workflow 中版本必须选定并固定。PR 只校验构建，main 推送执行部署，可提供手动触发；同一环境串行部署。

仓库 Pages 设置使用 GitHub Actions。默认 GitHub 域名，不要求用户购买域名。GitHub 用户名/仓库尚缺时，完成全部本地代码、文档和可配置流程，在实际发布前补齐身份及授权信息。不要因不知道用户名停止页面开发。

交付 deployment.md：首次配置、每次更新、查看失败日志、通过恢复已知正常提交并重新构建来回退。不要把 Pages 解释成可以运行 Node/Java 后端的服务器。

## 7. 开发顺序与完成定义

1. 迁移现有视觉到 Astro 组件；优先修复设计复核中的 D01～D07。
2. 建立内容集合、公开内容统一过滤和正式路由。
3. 完成列表分类、文章阅读、搜索、RSS、SEO。
4. 对生产构建进行桌面/手机、根路径/子路径检查。
5. 完成 GitHub Actions、写作指南和交付说明；资料齐备且具备授权后发布。

完成标准见 `02-设计复核与验收.md`。最终报告分别列出：代码已完成、测试已通过、内容仍待确认、公开部署是否完成。不能把本地服务启动当作发布成功。
