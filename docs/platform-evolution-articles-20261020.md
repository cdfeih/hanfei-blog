## 内容审校中的关键纠偏

### 元模型升级

- `userModified` 当前只在内容对齐分支阻止覆盖，删除分支没有相同豁免。正文按实现描述，没有照抄文档里的概括性“用户修改受保护”。
- 内容匹配认领是历史来源推断，不能证明该行一定由模板克隆；没有把相同内容称为零风险溯源。
- 当前没有删除墓碑，源行仍在时，缺失的目标行可能补回。
- 分组定义引用与宿主 ID 的映射口径不同，不能统一改写全部 Long 字段。
- 三方合并、认领预览、删除冲突处理均明确写为后续设计选项。
- 关联同步异常向外传播与实际数据库回滚验证分开说明，没有把升级全流程称为全有或全无。

### 数据库迁移

- 转换器与结构期望模型是相邻工具，未虚构一条共享统一中间表示的完整编译流水线。
- 转换器有通用回退路径，未声称顶层所有未知语法都被拒绝。
- 删除后插入只适合满足前提的种子，未冒充通用 upsert 等价转换。
- 索引等效检查不等于并发 DDL 原子性，也不修复 Flyway 历史。
- 没有将离线字符串与结构测试表述为目标数据库已执行通过。

### 富文本与虚拟表格

- 只说明阅读路径不创建编辑器，不虚构改造前性能数据。
- 1,000,000 的缓存预算按输入与输出 JavaScript 字符串长度计算，不称为精确 1 MB 内存上限。
- 固定策略下的内容缓存与未来动态策略切换分开讨论。
- HTML 清洗、资源来源限制、内容规模和渲染成本分别说明。
- 请求计数器处理 loading，不代表副作用具有旧响应保护。
- 没有将安全样本检查称为完整 XSS 审计，也没有声称已完成整表性能或拖拽验收。
