# 整体设计复核与开发验收

日期：2026-09-15。对象：交接包中的两页静态原型及分类筛选补丁。

## 1. 结论

**整体方向合理，适合技术负责人个人网站，建议保留并完善。** 首页能说明身份、职责和内容方向；蓝色与石墨灰配色一致；深蓝项目区与白底文章形成节奏；文章正文宽度适合中文技术阅读。

当前属于可用原型，尚未达到正式博客的交付标准。主要问题集中在首屏内容密度、小字号、分类与列表关系、手机文章目录以及导航状态。无需推翻设计，按下表调整即可。

用户已经认可视觉方向，不应让用户重新选择配色、组件库、字体或布局参数。开发者应依据规格处理这些设计细节，并展示结果。

## 2. 检查方法与证据边界

- 本轮实际查看桌面首页完整页面、文章桌面首屏及手机文章首屏。
- 桌面视口设为 1440×900；页面可用宽度实测 1425px（包含滚动条影响）。
- 手机视口设为 390×844；页面可用宽度实测 375px。
- 使用 DOM 测量核对正文宽度、字号、导航高度与目录位置；结合原型源码分析交互与发布差距。
- 前一轮已验证四分类筛选、恢复全部、空状态、键盘激活、主题切换与代码复制；本轮没有重复全部功能测试。
- 本轮没有进行全浏览器兼容、屏幕阅读器、200% 字号、完整颜色对比度或 Lighthouse 审计；这些列为正式开发验收项，不宣称已通过。
- 下表是开发待办。本次仅交付文档，未将其全部应用到原型。

## 4. 必须修正的问题

优先级定义：P0 为公开发布前必须处理的功能/内容问题；P1 为正式开发应完成的核心体验；P2 为可随内容增长完善的事项。没有把主观偏好当作故障。

| 编号 | 级别 | 当前证据 | 影响 | 明确调整要求 |
| --- | --- | --- | --- | --- |
| D01 | P1 | 图中英文编号 10px、文章元信息 12px、项目职责 13px、文章卡摘要 14px | 信息虽然能放下，但长期阅读吃力 | 正文/摘要 16px 起，必要标签 14px，装饰英文最低 12px；减少装饰优先于缩字 |
| D02 | P1 | 桌面 hero 实测约 666px；笔记区从页面约 841px 开始，卡片还在其后 | 900px 高首屏几乎看不到文章内容 | 压缩 hero 留白与图示至约 500～540px；在既定验收视口看到笔记标题，不设置强制满屏 hero |
| D03 | P1 | 分类栏是独立横条，与工程笔记标题、结果之间存在额外空间 | 看起来像网站领域说明，筛选对象不够明确 | 移到笔记标题之后、结果之前，中文说明「按主题浏览」；保留全部选项和选中态 |
| D04 | P1 | 手机 CSS 使用 order:-1；目录在标题前，实测标题距视口顶端约 377px | 读者还没看到文章标题，先看到目录 | 调整 DOM：标题/摘要/作者之后放默认折叠目录；屏幕阅读顺序与视觉一致 |
| D05 | P1 | 手机导航高度约 114px，但全站 scroll-padding-top 固定 100px | 锚点目标存在被遮挡风险 | 偏移随导航高度变化，增加 16px 安全间距；用目录与首页锚点实测 |
| D06 | P1 | 首页导航始终写死首页 active；工程笔记导航只跳本页锚点 | 当前区域/页面状态不准确，缺少完整文章入口 | 新增 /notes/；按路由及首页可见区域更新导航，最多一个当前项 |
| D07 | P1 | 分类状态只存在于 DOM，未保存到 URL | 刷新、返回不能恢复浏览上下文 | 列表分类参数写入 URL，处理 popstate；文章返回列表尽可能保留来源领域 |
| D08 | P0 | 草稿正文通过 article.html 可直接访问，只设置 noindex | 若原样发布，草稿仍会公开 | 正式站生产输出排除草稿；本地预览独立；公开索引也过滤草稿 |
| D09 | P1 | 目前只有一个草稿和两个准备中选题 | 一次访问容易误判网站主要是未完成内容 | 正式首页展示已发布文章；准备中清单留在写作计划。无文章时诚实展示简洁空状态 |
| D10 | P1 | 主题初始化在 defer 脚本中运行 | 深色访问可能出现浅色闪烁（代码推断，未做时序测量） | 首屏前初始化主题；系统偏好与用户选择优先级一致，存储失败可降级 |
| D11 | P1 | GitHub、联系入口尚未提供 | 个人推广的后续联系路径尚不完整 | 提供真实地址后加入；目前隐藏，不能编造或链接到示例账户 |
| D12 | P1 | 搜索、RSS、内容校验、部署流水线都尚未实现 | 原型不能直接承担长期内容维护 | 按产品规格实现，完成生产构建检查，不只复制 HTML |

补充判断：工作方法图是概念表达，足以承担首页的视觉识别，但不能作为个人成果证据。后续应以有实际问题、个人决策与验证记录的文章补充可信度。

## 5. 建议的正式首页排布

```text
导航：韩飞 / 首页 / 工程笔记 / 项目实践 / 关于 / 搜索与主题
┌───────────────────────┬──────────────────────┐
│ 个人定位、简介、阅读入口 │ 紧凑的工作方法示意图   │
└───────────────────────┴──────────────────────┘
工程笔记                       查看全部笔记
全部笔记  系统建模  复杂前端  平台架构  工程管理
筛选结果说明
精选文章卡
文章行（最多两项）
───────────────────────────────────────────────
深蓝项目区：项目价值说明 + SE-MBSE 角色与职责
───────────────────────────────────────────────
关于：姓名字标 + 简明介绍 + 真实联系入口
页脚：署名 / RSS / 回到顶部
```

手机顺序相同，图示紧凑化；筛选按钮自动换行，选择后不突然滚到远处。文章页顺序独立遵循正文优先，不复用首页巨大的 hero。

## 6. 验收清单

接手 AI 逐项记录通过/失败/未验证，并附必要证据。以下均为正式版本待验收标准，不是当前原型的完成声明。

### A. 视觉与阅读

- [ ] A01：320、390、768、1024、1440px 宽度检查首页、列表、文章、搜索；无整页横向滚动。
- [ ] A02：1440×900、100% 缩放下，首页可见工程笔记标题；大标题不重叠、不裁切。
- [ ] A03：文章正文 720～760px 最大宽度，手机留足边距，段落与代码字号满足规格。
- [ ] A04：390px 手机文章先见标题/摘要/作者，后见折叠目录；目录展开、关闭不遮挡正文。
- [ ] A05：两种主题的正文、次级文字、按钮、代码分别检查对比度；不用「整体看起来清晰」替代测量。
- [ ] A06：200% 文字放大仍能读取和操作；长标题、长英文标识符、窄屏表格有合理布局。
- [ ] A07：提供生产版本桌面首页、手机首页、桌面文章、手机文章、空分类和深色文章截图。

### B. 导航和筛选

- [ ] B01：每个导航和文章卡真实可用；刷新文章详情不会 404。
- [ ] B02：首页、列表和文章的导航高亮正确；首页项目/关于锚点的标题不被顶栏遮挡。
- [ ] B03：用多条不同领域的测试内容验证四分类，列表和计数一致；单篇多领域只计一次。
- [ ] B04：零条目分类有提示和恢复全部；只有一条文章时布局仍稳定。
- [ ] B05：复制带 topic 的 URL、新开页面、刷新、前进/后退，都能恢复选择；无效 topic 回到全部。
- [ ] B06：Tab/Enter/空格可操作筛选、主题、复制；焦点可见且没有键盘陷阱。

### C. 文章和内容隔离

- [ ] C01：新增 Markdown 后能自动进入列表、详情和索引，不手工修改多个页面。
- [ ] C02：重复 slug、未知领域、缺少发布日期、错误日期都能产生明确构建错误。
- [ ] C03：用带唯一标识文字的测试草稿构建正式站，搜索 dist、索引、RSS、sitemap、JSON，均找不到该草稿内容和链接。
- [ ] C04：草稿、未来发布日期文章均不生成公开路径；未来文章到期仍需重新构建才发布。
- [ ] C05：已发布测试内容只用于验证，交付公开内容前移除测试夹具，不能假冒韩飞成果。
- [ ] C06：目录处理重复标题、H2/H3、中文标点；点击后目标完整显示，当前项正确。
- [ ] C07：复制代码保留真实换行与尖括号；模拟剪贴板失败时有可操作提示。
- [ ] C08：JS 禁用时文章正文与列表仍可读，普通链接可打开，不显示依赖 JS 的假操作。

### D. 搜索与发现

- [ ] D01：生产构建生成 Pagefind 索引；中文如「模块边界」和英文如「React」有预期结果。
- [ ] D02：空搜索、无结果、加载、失败、重试均有明确状态；搜索只返回正式文章。
- [ ] D03：RSS XML 有效，条目地址和日期正确；sitemap 无草稿/搜索/404/原型页。
- [ ] D04：title、description、canonical 和结构化数据与当前页面一致，生产产物不含 localhost 占位配置。

### E. 部署与维护

- [ ] E01：全新 checkout 后按 README 和锁文件可安装、检查、构建、预览。
- [ ] E02：分别用 base `/` 和 `/hanfei-blog/` 构建并验证首页、详情、资源、搜索结果、RSS 与站点地图。
- [ ] E03：Actions 构建包含搜索索引；失败构建不发布，部署 artifact 仅 dist。
- [ ] E04：上线后从公网直接打开文章深层路径并刷新；正常显示自定义 404，资源无 404。
- [ ] E05：提供写作、发布、撤回、恢复旧版本的操作步骤。撤回公开文章不能保证互联网缓存同步消失，不承诺彻底删除历史访问痕迹。
- [ ] E06：记录性能测试条件与结果，不用开发服务器成绩代替生产测试。
