# 给开发 AI 的任务书

请基于本交接包，将「韩飞 · 工程与架构」个人网站原型开发成可长期维护、部署到 GitHub Pages 的正式静态博客。

## 先阅读

1. `00-交接说明.md`
2. `01-产品与开发规格.md`
3. `02-设计复核与验收.md`
4. `prototype/` 中的 HTML、CSS、JavaScript，实际运行首页和文章页。

## 已确定的方向

我叫韩飞，是 SE-MBSE 项目负责人，主要负责团队管理、技术方案和架构设计。网站用于推广个人技术能力，分享工程经验。我不懂设计，因此你需要负责整体排版、阅读体验、交互完整性和移动端适配，不要把这些设计决策反复交给我。

我已经认可原型的整体视觉。保留站名、蓝色与石墨灰、首页个人介绍和工作方法图、文章卡样式、深蓝项目区、中文技术阅读的整体气质。按复核清单改善字号、首屏高度、分类位置、手机目录、锚点偏移与导航状态，不要换成另一套模板。

## 实施要求

- 使用 Astro + TypeScript + Markdown/MDX，纯静态构建；使用 pnpm 并提交锁文件。
- 完成首页、工程笔记列表、文章详情、搜索、404、RSS、sitemap，以及首页项目/关于区域。
- 领域筛选真实生效，URL 能恢复状态，空分类有反馈。原型静态文字或假入口不能原样交付。
- 草稿仅在本地预览；正式站全部入口与构建产物排除草稿。原型文章是内容草稿，不是已获确认的项目成果。
- 首版不做实验室、评论、数据库、账号系统和在线编辑后台；优先把阅读和写作流程完成。
- 部署目标明确为 GitHub Pages，不替换为其他收费或专属托管服务，不要求购买服务器或域名。
- 处理 GitHub 用户站根路径和项目站子路径；搜索索引与 RSS 等都必须适配。
- 沿用已确认身份，未知的联系方式、团队规模、年限、业绩不要编造。
- 缺少 GitHub 用户名或正式内容时，先完成本地开发和可配置部署流程，到相应步骤再集中询问必要资料。
- 为准备公开的博客使用独立目录/仓库，不复制 SE-MBSE 内部配置、源码全集或业务数据。保留交接原型副本用于对照。

## 工作方式

先简要说明实施顺序，随后连续推进实现。你可以自主决定常规设计和实现细节，无需为按钮间距、字体等反复确认。完成后依据验收文档自查，修复实际发现的问题；不要只运行构建就宣布网站完成。

用少量测试内容验证文章、领域和搜索，测试夹具不得在公开站伪装成我的文章。涉及真实项目案例时，明确区分通用方法、概念示例和有证据支持的真实经历。

## 最终交付

1. 可运行的完整源码和依赖锁文件。
2. 本地启动、检查、生产构建、预览命令。
3. 网站与文章配置说明，以及一篇明确标记的本地草稿样例。
4. 适配 GitHub Pages 的 Actions 配置和首次部署指南。
5. 写文章、发布文章、修改与撤回文章的操作指南。
6. 桌面/手机/深浅色截图和逐项验收结果。
7. 如已获所需资料并完成部署，提供真实网址与线上验证结果；否则明确部署尚未完成及所缺信息。

文档中的正式规格优先于原型中尚未完善的细节。我的新反馈优先于旧方案。请从检查交接包并建立正式工程开始。
