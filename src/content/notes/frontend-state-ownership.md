讨论前端状态管理时，话题经常很快滑向"用哪个库"。但混乱的项目换任何库都混乱：问题的根源是状态的所有权没有被定义。

## 三类状态，三种归属

1. **服务端数据的缓存**：归属数据层，组件只是消费者
2. **跨组件的交互状态**：归属最近公共父级或独立状态容器
3. **局部 UI 状态**：归属组件自身，不进全局

多数"全局状态越来越乱"的项目，是把第三类甚至第一类都塞进了第二类的容器里。

## 一个判定问题

> 当这个状态失效时，影响范围是什么？

如果重置一个状态需要手动清理五个地方，说明所有权已经被稀释；如果它只在定义处更新，边界就是清晰的。

```ts
// 示意：缓存状态与 UI 状态分离
const useModelList = () => useQuery('model-list', fetchModels); // 服务端缓存
const usePanelOpen = () => useState(false); // 局部 UI 状态
```

## 迁移策略

把所有权说清楚之后，存量代码的迁移可以渐进进行：

- 新功能直接按规则落地
- 触碰到的高频改动模块优先重构
- 其余保持现状，不做无收益的整理

状态治理的目标是降低变化成本，而不是追求形式上的统一。
